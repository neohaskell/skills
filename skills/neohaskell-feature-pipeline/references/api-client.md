# API and client route

Follow [nh-api-client](../../nh-api-client/SKILL.md) across backend serialization, the contract served at the configured URL, and affected callers. Use the relevant command/query implementation skill for backend changes. When frontend client work is in scope and its frontend or generation/build tooling is missing, use [nh-frontend-setup](../../nh-frontend-setup/SKILL.md) and resume client alignment; otherwise run the existing application mechanism. Setup owns the URL-to-generation-to-compilation contract.

Use [nh-frontend](../../nh-frontend/SKILL.md) for UI work within the requested outcome. A full-stack feature continues through the interface; an explicitly API-only request retains that boundary. Check optional versus null fields, enums, error responses, authentication, URLs, transport, and uploads where applicable. Simulated transport proves client behavior against fixtures. Claim real interoperability only after exercising the configured backend with the intended identity and observing the requested result; this does not require deployed-revision proof. Evolve published contracts through [neo-immutability-and-versioning](../../neo-immutability-and-versioning/SKILL.md).
