# Business behavior and effects

1. Read the application's domain vocabulary and current behavior. Use [discovery](../../augment-feature-request/SKILL.md) only for gaps; use [event-modeling](../../event-modeling/SKILL.md) for changed commands, facts, projections, and applicable UI nodes. Correct the design document when needed while preserving unrelated work and persisted history.
2. Ask [verify-event-model](../../verify-event-model/SKILL.md) to inspect the design independently of editing. Resolve structural defects; treat naming advice according to its actual impact.
3. Follow [outside-in TDD](../../neohaskell-outside-in-tdd/SKILL.md) for each behavior. Select [HTTP](../../write-hurl-e2e/SKILL.md), [in-domain acceptance/properties](../../write-feature-tests/SKILL.md), and [unit tests](../../write-unit-tests/SKILL.md) at the boundaries the task reaches. Introduce [domain types](../../neohaskell-domain-modeling/SKILL.md) when the behavior needs them.
4. Implement the relevant [command](../../implement-command/SKILL.md), [event and replay](../../implement-event-and-update-entity/SKILL.md), [entity evolution](../../expand-entity/SKILL.md), [query](../../implement-query/SKILL.md), and [integration](../../implement-integration/SKILL.md), then [wire the backend](../../wire-feature/SKILL.md). Read only the branches used by this slice.
5. Complete [API/client](../../nh-api-client/SKILL.md) and [frontend](../../nh-frontend/SKILL.md) work when requested. Observe the specific created entity and any requested external effect through bounded waits. Distinguish accepted, pending, failed, retried, and completed outcomes. Temporary stubs can support development but cannot close an effect-bearing request.
