# NeoHaskell Application Skills

Vocabulary for the collection of skills used to develop full stack applications with NeoHaskell.

## Language

**Consumer application**: A product that uses NeoHaskell to implement its business behavior and interfaces. Avoid calling the consumer product the framework.

**Application skill**: A skill responsible for helping develop or verify a consumer application.

**Shared skill**: A skill expressing a principle or procedure reusable across applications and framework work, with explicit applicability limits.

**Framework-internal skill**: A skill for developing, maintaining, or publishing NeoHaskell itself. Its presence in source material does not make it part of the application collection.

**Adapted copy**: A source skill maintained in this collection with the changes needed by consumer applications.

**Omakase foundation**: The shared skills whose philosophy is adopted as one integrated approach, without selecting each principle again.

**Application catalog**: The approved set of skills and resources in the consumer application collection. Its membership differs from the candidate skills found in the framework.

**Collection version**: An identifiable edition of the application skills and their resources, maintained together. It is distinct from the installer version and the framework revision used by a consumer application.

**Managed skill**: A skill installed in a consumer application whose content is maintained by this collection. Application customizations are kept as separate extensions.

**Application extension**: An instruction or procedure maintained by a consumer application to complement managed skills.

**Collection maintenance skill**: The single skill responsible for guiding explicit collection version changes and recovery in a consumer application. It is distinct from application feature-development skills.

**Application journey**: The capabilities needed to complete a requested consumer application change. Its scope follows the requested result and may include UI, client, backend, or integrations.

**Observable delivery**: The result requested by the consumer, distinguished from preparation or initial acceptance. A pending effect is not a completed delivery when that effect belongs to the request.
